# Unassessed attempts are recorded, best-effort

Extends ADR-0003 and ADR-0013. Early users found that a failed queued assessment left no record, so the audit trail showed nothing of an attempt that had been made, and paid for when the Engine responded unusably. Every Unassessed attempt, sync or queued, thrown or returned, is now recorded in the same `judgment_assessments` table as the Assessments, so each attempt per Subject is visible in one place. A failed record holds the `EngineFailed` class and message and, when the Engine responded with something unusable, its Provenance. It never holds answers or an Outcome, so it can never be rebuilt, decided, cached or put in Review, and a failure still cannot become a default Outcome.

The attempt is recorded before `EngineFailed` is thrown or `Unassessed` is returned, and `Unassessed` and `AssessmentFailed` carry the record. Recording it is always best-effort, whatever `judgment.persistence.required` says. ADR-0013 refuses an unrecorded Assessment so that no unrecorded consequential judgment is acted on, but an Unassessed result cannot be acted on at all, so refusing it protects nothing, and replacing the Engine's failure with a database error would hide the cause the application needs to handle. A failed write is reported as `UnassessedNotRecorded` and logged, and the original failure surfaces unchanged.

Existing installs get a second migration stub that alters the table: `answers` and the Provenance columns become nullable, and failure columns are added. The v0.1.0 create stub is not rewritten, so a published copy never diverges from what is shipped. As a consequence, `latestAssessment()` returns the latest attempt, which may be Unassessed, and the `answered()` and `unassessed()` scopes tell the two kinds apart.
