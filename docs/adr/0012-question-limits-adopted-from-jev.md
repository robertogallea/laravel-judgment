# Question limits are adopted from Jev as package limits

A Classification accepts 2–255 distinct labels and a Rating 2–10 levels. The upper bounds are Jev's documented limits; the package adopts them as its own rather than leaving each Engine to reject what it cannot answer, so a Question that could not be asked fails where it is written instead of at the first Engine round in production. This is a deliberate exception to ADR-0002: the limits are named in package terms, and any future Engine must support at least 255 labels and 2–10 levels to implement the contract. Should an Engine with narrower limits ever be added, it rejects Questions it cannot answer at its own boundary; the package limits are not lowered for it. The lower bounds are the package's own: a Classification with one label chooses nothing, and a Rating with one level orders nothing.

Labels and levels are required arguments of the named constructor (`Classification::of($question, labels: …)`, `Rating::of($question, levels: [...])`), not a chained step as in the API-feel prototype, so an incomplete Question cannot be constructed at all; chained methods are kept for optional refinements such as `Likelihood::means()`.
