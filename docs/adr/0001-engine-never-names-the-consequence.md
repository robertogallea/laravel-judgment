# The engine never names the consequence

Questions sent to an Engine must be about the subject ("how likely is this refund request abusive?"), never about the action ("should this refund be approved?"). Outcomes such as approve/review/reject are produced only by an application-owned, deterministic Decision and never appear in an Engine's prompt or schema. We chose this so that the separation between probabilistic assessment and deterministic consequence is structural rather than conventional, so thresholds are meaningful (a probability of "abusive" is coherent; a probability of "approve" is not), and so a human-reviewable, auditable Decision always sits between the model and any effect on a person. Consequence: judgments are named after their subject or concern (`refund-abuse`), not after actions (`approve-refund`).
